CONFIGURABLE WORKFLOW - HOW TO MERGE
=======================================
Implements the "workflow should be configurable, not hard-coded"
principle from your architecture document. Each Application Type (Leave
Application, NOC Request, etc.) already had a "default_authority_role"
field that was never actually used - this wires it up for real, and
adds a second option (route_to_admin_office) for types that should
always go to a central office (Finance, Registrar) instead of the
applicant's own department.

Tested end-to-end: same-department routing, admin-office routing, the
API endpoint, and session-authenticated web requests all pass.

STEP 1 - REPLACE these files at the same path in ME_ERP:
  applications/models.py
  applications/admin.py
  applications/services.py       (NEW FILE)
  api/views.py
  api/urls.py
  config/settings.py
  templates/applications/form.html

STEP 2 - ADD this new migration file:
  applications/migrations/0004_applicationtype_route_to_admin_office.py

STEP 3 - Apply it:
  python manage.py migrate

STEP 4 - Configure your application types (as the admin, no code):
  Go to /admin/ -> Application types -> open any type (e.g. "Leave
  Application") -> set "Default authority role" (who normally handles
  this) and tick "Route to admin office" only for types that should
  always go to a central office instead of the applicant's department.

STEP 5 - Push to GitHub so Render redeploys:
  git add .
  git commit -m "Make application routing configurable per type"
  git push
